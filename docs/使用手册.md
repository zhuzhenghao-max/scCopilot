# scCopilot 使用手册

> 面向 Qoder 高校创造力大赛答辩 · 2026-11-17

---

## 一、项目概述

scCopilot 是一个**单细胞 RNA 测序数据分析 + AI 细胞类型解读**工作台。它把 Scanpy 标准流水线（QC → 归一化 → HVG → PCA → 邻居图 → Leiden 聚类 → UMAP → Marker 提取）封装成一条可复现的 Pipeline，并在聚类结果上叠加多智能体 AI 解读——**每一个结论都能追溯到具体的 marker 基因证据**。

### 核心能力

| 能力 | 说明 |
|------|------|
| **一键流水线** | 上传 .h5ad 或使用内置演示数据，自动完成全部分析 |
| **交互式 UMAP** | 点击任意细胞 → 选中其所在簇 → 右侧实时出 AI 解读 |
| **多智能体工作流** | Planner → Annotator → Critic 三阶段，Critic 负责防幻觉 |
| **知识图谱检索** | 内置 20 种免疫细胞 Cell Ontology，用 Jaccard 相似度匹配 marker |
| **表达层核实** | 名字对上只是嫌疑：逐个 marker 统计簇内实测检出率，全簇静默直接拦下 |
| **簇内异质性判定** | 一簇未必是一类细胞：判别基因 + 簇外参照 z 分逐细胞判型，主标签盖不住七成就不给整体命名 |
| **响应缓存** | 同一 prompt + 同一模型只敲一次网关，第二次逐字复现，卡片标"本地缓存命中" |
| **状态机引擎** | raw → qc_passed → embedded → clustered，非法转换抛 StateError |
| **审计追踪** | ProvenanceTracker 记录每步操作的工具名、参数、耗时 |
| **局部刷新** | st.fragment 隔离右侧面板，点 UMAP 不重跑整个页面 |
| **防幻觉机制** | 证据不足时 AI 主动拒绝回答，红色警告框展示原因 |

## 二、环境准备

### 2.1 系统要求

- Python 3.10+
- Windows / macOS / Linux
- 建议 8GB+ 内存（首次运行需 numba JIT 编译约 60s）

### 2.2 安装依赖

```bash
cd scCopilot
pip install -r requirements.txt
```

**核心依赖：**
- `streamlit>=1.40` — 前端框架（支持 st.fragment）
- `scanpy>=1.10` — 单细胞分析引擎
- `anndata` — 数据结构
- `plotly` — 交互式图表
- `openai` — LLM API 调用（可选）

**可选依赖：**
- `streamlit-plotly-events` — UMAP 点击事件（已做 graceful fallback）
- `scrublet` — 双细胞检测（默认关闭）

### 2.3 配置 LLM（可选）

在项目根目录创建 `.env` 文件：

```ini
LLM_API_KEY=sk-xxxx
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_MODEL=qwen-plus
```

**不配置也能用**：系统会自动退回本地知识库规则推断，并在 AI 卡片上标注"未调用大模型"。

DeepSeek V3 实测可用（`LLM_MODEL=deepseek-chat` 即 V3）。用它是因为任何 OpenAI 兼容网关
都走同一条 `_post_chat` 路径，换供应商只是改这三行；Key 只进 `.env`（已被 `.gitignore`
忽略），代码里一律 `os.getenv` 读取。

## 三、快速开始

### 3.1 生成演示数据

```bash
python scripts/make_demo_h5ad.py
```

这会在 `data/raw/` 下生成一个包含 5 种免疫细胞（T cell、B cell、NK cell、Monocyte、Dendritic cell）的模拟 .h5ad 文件。

### 3.2 启动应用

```bash
streamlit run app/main.py
```

浏览器会自动打开 `http://localhost:8501`。

### 3.3 三步跑通

1. **左侧「数据来源」** → 选择「使用内置演示数据」（或上传自己的 .h5ad）
2. **其余参数保持默认** → 页面自动跑完流水线（首次约 1 分钟）
3. **在 UMAP 上点一个细胞** → 右侧卡片逐字给出细胞类型判断、置信度与理由

**建议演示顺序：**
- 把 Leiden 分辨率从 1.0 拖到 1.6，看簇被切开
- 点那个线粒体偏高的簇，看 AI 如何拒绝编造

## 四、界面说明

### 4.1 侧边栏（左侧）

| 控件 | 功能 |
|------|------|
| 数据来源 | 上传 .h5ad 或使用演示数据 |
| QC 阈值 | min_genes / max_genes / min_counts / max_pct_mito（表单内，点「应用参数并重跑」生效） |
| HVG 参数 | n_top_genes / hvg_flavor（同上，表单提交生效） |
| PCA | n_pcs（同上，表单提交生效） |
| 邻居图 | n_neighbors（同上，表单提交生效） |
| Leiden 分辨率 | 滑块实时调整，秒级重聚类 |
| Marker 数量 | Top N 差异基因 |
| AI 开关 | 是否自动解读 / 是否调用 LLM / 是否开启动画 |

**调参性能设计（2026-11-17 实测）**：首次跑批含 numba JIT 编译约 40–60s（默认自动预热一次）；
编译后每次全量重跑约 10s。QC/嵌入参数放进表单是为了避免"每拖一次滑块就重跑一遍"；
结果按参数指纹缓存在会话里，切回已跑过的参数组合直接恢复、零等待（toast 提示"已直接恢复缓存结果"）。

### 4.2 左半屏

- **UMAP 散点图**：每个点 = 一个细胞，颜色 = 簇 ID 或基因表达量
- **看一个基因**：「UMAP 着色」选最后一项 → 输入基因名，图上直接按该基因着色，下面再给一张
  逐簇点图（点位置 = 簇内平均表达，点大小 = 簇内检出率）。取值用 `adata.X`（log CPM+1），
  与 marker 条形图同一层，所以「AI 说这是 T 细胞 → 我自己看 CD3D」这条复核路径不需要回命令行。
  基因名大小写不敏感（小鼠 `Cd3d` 也能命中）；命中 0 个或重名列时**不画**并说明原因，
  绝不猜一个相近的名字给你看。
- **条形图**：当前选中簇的 Top marker 基因。「条形图显示前几个基因」滑块的上限 = 本簇实际算出的
  marker 行数（受侧栏「每簇 Top 基因数」约束，默认 8），不再写成固定 4–20——超出行数的那段
  拖了不会有任何变化，所以直接砍掉；把「每簇 Top 基因数」调大后上限会自动放宽。
- **簇一览表**：每簇的细胞数、中位 UMI、中位线粒体占比、证据是否充足

### 4.3 右半屏（st.fragment 局部刷新）

- **AI Copilot 卡片**：预测细胞类型、置信度、引用基因、防幻觉告警
- **Agent 思考过程时间线**：Planner → Annotator → Critic 三阶段可视化
- **知识图谱候选**：KG 检索到的 Top 5 候选细胞类型
- **推断理由**：打字机效果逐字输出
- **证据表 / 闸门判定 / 模型原文**：证据表是 `rank_genes_groups` 的原始统计量——平均表达、
  簇内检出率、log2FC、wilcoxon 打分、BH 校正 p（`core/pipeline.py` 从一开始就算了两列，
  之前只是没显示）；条形图 hover 同样给 log2FC 与校正 p。缺列时宁可留空，不会凭空补数字。
- **参数解读卡片**：调分辨率时发生了什么（拆分/合并统计）
- **QC 漏斗 / 耗时 / 导出**：完整审计信息。AI 结论每次渲染都按当前解读缓存写回
  `obs['sccopilot_type' | '_conf' | '_source' | '_het']` 与簇表同名列：模型拒答或被 Critic
  升级的簇只写 `low_confidence`（不写具体类型），没解读过的写 `unannotated`，
  `uns['sccopilot_annotation']` 留写回时间与判定口径。落盘的 h5ad 与簇表 CSV 都带这几列，
  点「落盘」后可直接下载（>150 MB 只给路径，不塞进浏览器）。

## 五、新功能详解

### 5.1 多智能体工作流

每次 AI 解读都会经过三个阶段：

1. **Planner（规划者）**
   - 评估证据是否充足（marker 数量、表达量）
   - 决定是否调用 LLM
   - 输出执行计划（kg_top_k）

2. **Annotator（标注者）**
   - 调用 `kg_retriever.retrieve(marker_genes)` 检索知识图谱
   - 构建 prompt（复用 `ai.explainer.build_cluster_prompt`）
   - 调用 LLM API 或本地规则推断
   - 返回 `Interpretation` 对象

3. **Critic（审查者）**
   - 检查预测类型是否与 KG 候选一致
   - 检查证据是否充足（n_usable >= 3）
   - 如果冲突或薄弱 → 返回 `{"status": "escalate", "reason": "..."}`
   - 否则 → 返回 `{"status": "approve"}`

**防幻觉机制**：当 Critic 返回 escalate 时，界面会显示红色警告框，明确告知用户"AI 主动拒绝回答"及原因。

### 5.2 知识图谱检索

`core/kg_retriever.py` 内置了 20 种免疫细胞的 Cell Ontology：

```python
CELL_ONTOLOGY = {
    "CL:0000624": {"name": "CD4+ T cell", "parent": "CL:0000084", "markers": ["CD3D", "CD3E", "CD4", "IL7R"]},
    "CL:0000625": {"name": "CD8+ T cell", "parent": "CL:0000084", "markers": ["CD3D", "CD3E", "CD8A", "CD8B"]},
    # ... 共 20 种
}
```

检索算法：
1. 计算 marker 基因与每种细胞类型的 **Jaccard 相似度**
2. 如果父类也在候选里，**+0.1 加分**（层级一致性）
3. 返回 Top K 候选

#### 5.2.1 表达层核实（`core/kg_expression.py`）

Jaccard 只比基因名，回答不了"这个 marker 在这簇里到底有没有表达"。名字对上但表达为 0，
是单细胞注释里最典型的假阳性：参考列表写着 CD3D，本簇 Top 基因也排出 CD3D，
可那只是 log2FC 顶出来的噪声峰，簇内只有 2% 的细胞真的检测到它。

所以候选出来后，逐个 marker 在该簇的细胞上实测：

| 字段 | 口径 |
|------|------|
| `pct_expressed` | 簇内 `X > 0` 的细胞比例（counts 与 log1p 矩阵同口径，不受归一化影响） |
| `mean_expr` | 簇内平均表达量（仅 log1p 矩阵有可比性，输出里用 `unit` 标明） |
| `support_ratio` | 达标的 marker 数 / 矩阵里找得到的 marker 数 |

Critic 增加一条硬规则：**谱系一致但 `support_ratio < 0.34` → escalate**，理由里直接写
"名字对上了但表达不支持（静默：CD3D、CD4；support_ratio=0.00 < 0.34）"。
阈值取 1/3 而不是 1.0：一条 3 个 marker 的候选只要有 1 个实打实表达就不误伤，
但"全簇静默"这种名字重合型假阳性一定拦住。

矩阵里根本没有的基因计入 `missing`，不算证据也不判造假——它说明的是注释没对齐。

不传 `adata` 时整段跳过，工作流行为与旧版一致（谱系/证据两道审查仍在）。

#### 5.2.2 簇内异质性判定（`core/heterogeneity.py`）

上面两道审查都建立在"一簇 = 一类细胞"这个假设上。Leiden 分辨率 1.0 时 CD4+ T 和单核
细胞常被压进同一簇：Top 差异基因两头的 marker 各出几个，本地投票和 KG 检索都会给出一个
"看起来合理"的混合答案，谱系审查和表达核实都拦不住（每个 marker 单独看都真的在表达）。
这时唯一诚实的结论是**这一簇不该整体命名**。

判定分五步，每个数字都能在 X 矩阵上逐细胞复算：

| 步骤 | 口径 | 常量 |
|------|------|------|
| ① 候选类型 | 本簇 Top 基因投票 + 知识库参照类型，凑成面板 | `ai/gene_kb.heterogeneity_panels` |
| ② 判别基因 | 只保留"别的候选类型面板里没有"的基因 | `MIN_PANEL_GENES = 4` |
| ③ 打分 | 判别基因平均表达，相对**簇外参照细胞**标准化成 z 分 | 参照上限 `REF_MAX_CELLS = 4000` |
| ④ 单细胞判型 | 取最高 z，但必须 `z ≥ 0.5` 且领先第二名 `≥ 0.3`，否则记 Unassigned | `MIN_Z` / `MIN_MARGIN` |
| ⑤ 分布判定 | 主标签占比 <70% 且第二个**真实类型** ≥15% → 混合；熵一并汇报 | `MIN_DOMINANT_PROP` / `MIN_RUNNER_UP_SHARE` |

两条容易被问到的取舍：

- **为什么剔除共享 marker**：真实数据实测，NK 簇里 CD8+ T 面板一个判别基因都没有
  （CD8A/CD8B 不在这份矩阵里），却靠共享的 GNLY/NKG7/PRF1 抢走 49% 的细胞，把干净的
  NK 簇读成"混了 CD8"。共享基因证明的是"有细胞毒程序"，不是"有第二种细胞"。分不开的类型
  不参与判型，卡片上会写明"CD8+ T 细胞只有 0/4 个判别基因，和 NK 细胞分不开"。
- **为什么不用 `sc.tl.score_genes`**：它的对照组是"传进去那些列"的分箱抽样，切片方式一变
  分数量纲就变（演示数据实测：面板并上 2000 个 HVG 时 gap 中位 0.133–0.144、低质量簇 0.222；
  同一簇改用全基因 2452 列则是 0.147–0.166 / 0.246；只喂面板基因时对照组根本取不出来，
  `RuntimeError: No control genes found in any cut`，复跑 `_research/diag_scoring_space.py`），
  于是绝对阈值 `margin=0.5` 把 5 个簇的主标签全读成 Unassigned——连 marker 检出率 98–100%
  的干净 T/B/单核/NK 簇也只有 3%–5% 的细胞判读得出（低质量簇 19%），Critic 把所有结论都拦下来。
  参照细胞 z 分没有这个问题，也不引入随机对照组。

"第二种细胞"只认真实类型：Unassigned 多属于"面板读不出来"（ambiguous），不是混了第二种
细胞。踩过的那一刀是 64% T + 35% Unassigned 被判成混合簇。

亚簇拆分只在分布确实分歧时才做（省时间），PCA 空间取"判别基因 ∪ 全数据集 HVG"这个中立
空间：只用判别基因的话任何分歧都会被拆成两个纯净亚簇，结构/噪声之分就自证预言了。拆分后
按亚簇多数投票算加权纯度，纯度比整簇主标签占比高出 ≥10% 才算"分歧成片"（真有两个亚群），
否则报"零散噪声或过渡状态"。

实测（`python -X utf8 _research/check_heterogeneity.py` 与 `_research/check_expression.py`）：

| 场景 | 判定 | 关键数字 |
|------|------|----------|
| 演示数据 簇 0 / 1 / 2（T / B / 单核） | homogeneous | 主标签 100%，判读得出 100% |
| 演示数据 簇 3（NK） | homogeneous | NK 98%，Unassigned 2% |
| 演示数据 簇 4（低质量） | ambiguous → Critic escalate | 只有 7% 的细胞判读得出 |
| 合成 250 T + 150 B 同簇 | heterogeneous | 62.5% / 37.5%，熵 0.95 bit，亚簇纯度 100%（增益 37.5%） |
| 合成 逐细胞抽签 | heterogeneous | 50/50 但纯度增益 6%<10% → 报零散噪声，不报亚结构 |
| 合成 380 T + 20 B | homogeneous | 主标签 95%，少数那头 5%<15% |
| 单簇数据集（簇外参照 20 个细胞） | not_assessed | 没有参照系，不硬给相对结论 |

阈值 0.7 不是拍的：mLLMCelltype 判"争议簇"用的 `consensus_proportion` 就是 0.7，
CellTypist 的 `majority_vote(min_prop=0.9)` 作用在亚簇标签上更严。全部阈值原样写在返回值
`params` 里，前端卡片底部整份展示——评委问"70% 从哪来"，答案是代码里的常量加这段理由。

### 5.3 状态机引擎

`core/pipeline.StateAwarePipeline` 封装了流水线状态转换：

```
raw → qc_passed → embedded → clustered
```

- 每次状态转换都会调用 `ProvenanceTracker.log_step()` 记录审计信息
- 非法转换（如跳过 QC 直接 embedding）会抛出 `StateError`
- 提供 `run_full()` 一键跑完全流程

### 5.4 审计追踪

`core/provenance.ProvenanceTracker` 记录每步操作：

```python
tracker = ProvenanceTracker()
tracker.log_step("apply_qc", {"min_genes": 200}, {"n_cells": 2240}, duration_s=1.5)
report = tracker.export_json()
# {
#   "session_start": 1700000000.0,
#   "total_steps": 1,
#   "steps": [{"tool_name": "apply_qc", "params": {...}, "result_summary": {...}, ...}]
# }
```

前端在「QC 漏斗 / 耗时 / 导出」区域展示完整溯源报告。

### 5.5 局部刷新（st.fragment）

右侧 AI 面板被包裹在 `@st.fragment` 装饰器中：

```python
with right:
    @st.fragment
    def ai_panel_fragment(cluster_id: str):
        render_ai_card_with_trace(cluster_id, result, params)
        render_resolution_card(result, params)
        render_run_info(result, params)
    ai_panel_fragment(selected)
```

**效果**：点击 UMAP 只刷新右侧面板，不重跑整个页面，响应速度从 3-5s 降到 <1s。

### 5.6 响应缓存（`LLM_CACHE`）

大模型是这套系统里唯一的非确定环节。为了让"每个数字都能复现"这句话在大模型这一层也成立，
`_post_chat` 在真正发请求前先按 `sha256(model + base_url + temperature + system + user)`
查一次本地缓存：

- 命中 → 直接返回首次的回复，**不再产生 API 调用**，卡片 meta 显示"本地缓存命中 · 首次请求 <时间>"；
- 未命中 → 请求成功后原子落盘到 `data/cache/llm/<hash>.json`（先写 `.part` 再 rename），
  文件里只有 `content / model / temperature / created_at`，**Key 与请求头都不写**；
- 换模型或换 temperature → 哈希变化，不会拿旧模型的答案冒充新模型；
- `LLM_CACHE=0` 关闭，`LLM_CACHE_DIR` 改目录；`data/cache/` 已在 `.gitignore` 里。

代价是：网关侧改了模型版本而本地没察觉时，缓存会一直给旧答案。所以卡片上明写"本地缓存命中"，
不假装这是一次新调用；要重跑就删 `data/cache/llm/` 或设 `LLM_CACHE=0`。

### 5.7 静态演示站（`web/`）

答辩现场可能没有网络或没有 Key，所以另有一份**纯静态、无构建**的演示站：数据由
`scripts/export_site_data.py` 在本机真实跑批后冻结成 `web/data/{normal,resolution,unannotated}.json`
+ `manifest.json`，前端只有 `index.html` + `css` + `js/app.js`（plotly.js 画可点击 UMAP），
不接大模型（`use_llm=False`），断网也能打开。

- **证据表与工作台同口径**：静态站证据表也列到「校正 p」（BH 校正），格式与 Streamlit 端

## 八、常见问题

### Q1: 首次运行很慢（60s+）？

**A**: 正常。Scanpy 依赖 numba 做 JIT 编译，首次调用会编译底层算法（应用默认先自动预热一次）。
预热后调 QC 参数的全量重跑约 10 秒；改完参数要点「应用参数并重跑」才会重算，
已跑过的参数组合有会话缓存，切回去立即恢复。只调分辨率走快路径，秒级。

### Q2: 没有 LLM_API_KEY 能用吗？

**A**: 能。系统会自动退回本地知识库规则推断，AI 卡片上会标注"未调用大模型"。

### Q3: 点击 UMAP 没反应？

**A**: 检查侧边栏「点击 UMAP 后自动解读」是否开启。如果关闭了，需要手动点"开始解读该簇"按钮。

### Q4: AI 返回"证据不足，建议人工复核"？

**A**: 这是 Critic 的防幻觉机制在起作用。可能原因：
- marker 基因数量太少（< 3）
- 预测类型与 KG 候选不一致
- 表达量偏低

### Q5: 如何上传自己的数据？

**A**: 左侧「数据来源」→「上传 .h5ad 文件」。要求：
- 格式：AnnData .h5ad
- 必须包含 `X`（表达矩阵）
- 可选 `obs`（细胞注释）和 `var`（基因注释）

### Q6: 如何导出结果？

**A**: 右侧「QC 漏斗 / 耗时 / 导出」区域：
- marker 表 CSV（含 `scores` / `pvals` / `pvals_adj` / `logfoldchanges` / `mean_expr` / `pct_expressed`）
- 簇表 CSV（含 `sccopilot_type` / `sccopilot_conf` / `sccopilot_source` / `sccopilot_het`）
- 解读报告 MD（如果已生成 AI 解读）
- 落盘 h5ad + 表格到 `data/processed/`，落盘后可直接点下载拿回浏览器
  （>150 MB 只给磁盘路径）。h5ad 的 `obs` 里带着上面那四列注释，
  `uns['sccopilot_annotation']` 是写回时间与判定口径，可以直接进 Scanpy/Seurat 的下游分析。

### Q7: 为什么第二次点同一个簇，回答一字不差？

**A**: 命中了响应缓存（`data/cache/llm/`）。这是故意的：大模型是唯一的不确定环节，
缓存让同一份输入在演示里可逐字复现，也避免重复计费。卡片 meta 会写"本地缓存命中 · 首次请求 <时间>"。
想每次真打网关：`.env` 里设 `LLM_CACHE=0`；想重来：删掉 `data/cache/llm/`。

### Q8: AI 说"T 细胞"，但知识图谱候选里 CD4/CD8 都没表达，怎么看出来？

**A**: 展开「知识图谱候选细胞类型」，每个候选后面有两组数：**名字重合分** 和 **簇内实测检出率**
（如 `检出 5/5 · support_ratio=1.00`，逐个 marker 给出 `CD3D=100%`）。
名字对上但表达为 0 的候选，Critic 会直接 escalate 并把静默基因列在拒绝理由里。

### Q9: 为什么某个簇被判"不建议整体命名"？

**A**: 那是簇内异质性判定（5.2.2）在起作用：这一簇里逐细胞判型后主标签盖不住七成细胞，
或太多细胞本次面板判读不出归属。卡片上「🧬 簇内异质性判定」会给出主标签占比、熵、
判读得出的比例和（如果做了）亚簇拆分纯度；Critic 的拒绝理由直接引用这串数字。
下一步要么调高 Resolution 把它拆开，要么人工复核 UMAP 上是不是一团过渡态。
**这不是模型"心情不好"**：同一份数据重跑，这些数字逐字不变（`tests/test_heterogeneity.py`
里 `test_numbers_reproduce_exactly` 钉住了这条）。

### Q10: 我想上传 .h5ad，结果出现"开始使用"引导页，是要我装依赖吗？

**A**: 不是。那是**当前没有可用数据源**时的空状态引导——选了「上传 .h5ad 文件」但还没把文件
拖进上传框（或上传还在进行）时就是这一屏。命令行安装步骤收在折叠区里，正常用不到：
依赖在 2.2 一次装好就够了。拖入文件后页面会自己开始跑流水线。
若文件本身读不出来，目前给的是 Streamlit 的红色异常框（这条路径还没有专门的友好提示，
属于已知待改进项），把最后一段异常贴出来就能定位问题。

## 十、答辩演示脚本

### 10.0 上台前 5 分钟自检

```bash
python -X utf8 scripts/release_check.py --skip-tests    # 发布物三类检查，秒级
python -X utf8 scripts/check_app_llm.py 8502            # 真实 LLM 链路 + 截图取证（需先起服务）
```

前者保证静态站数字自洽、`dist/` 没落后、发布物里没有密钥；后者确认卡片真的走到大模型、
console 零报错，并把卡片截图写到 `docs/screenshots/`。两条都退出码 0 再上台。

### 10.1 开场（1 min）

> "大家好，今天介绍 scCopilot——一个单细胞数据分析 + AI 解读工作台。它的核心卖点是：**每个 AI 结论都能追溯到具体的 marker 基因证据，证据不足时 AI 会主动拒绝回答，而不是编一个名字给你。**"

### 10.2 演示流水线（2 min）

1. 启动应用：`streamlit run app/main.py`
2. 选择演示数据，保持默认参数，点击"开始分析"
3. 等待 60s（首次 numba 编译），展示 UMAP 和簇一览表
4. 点击一个簇，展示右侧 AI 卡片（预测类型、置信度、引用基因）

### 10.3 演示多智能体工作流（2 min）

1. 展开「Agent 思考过程时间线」，讲解 Planner → Annotator → Critic 三阶段
2. 展开「知识图谱候选」，展示 KG 检索结果，指出**每个候选后面的第二个数字**：
   "名字重合 0.62 只是嫌疑，簇内实测 CD3D=100%、TRAC=99% 检出才是证据。
   如果哪一天名字对上但检出率是 0，Critic 会当场拒答——这是名字层面假阳性的克星。"
3. 点击一个线粒体偏高的簇，展示 Critic 返回 escalate，红色警告框出现
4. 强调："这就是防幻觉机制——证据不足时 AI 主动拒绝回答"

### 10.4 演示局部刷新（1 min）

1. 快速点击不同簇，观察右侧面板实时刷新
2. 强调："st.fragment 隔离了右侧面板，点 UMAP 不重跑整个页面，响应 <1s"

### 10.5 演示调参（1 min）

1. 拖动 Leiden 分辨率滑块从 1.0 到 1.6
2. 观察簇被切开，「参数解读卡片」展示拆分/合并统计
3. 强调："只动分辨率走 recluster 快路径，秒级响应"

### 10.6 总结（1 min）

> "scCopilot 的四个技术亮点：
> 1. **状态机引擎**：raw → qc_passed → embedded → clustered，非法转换抛 StateError
> 2. **多智能体工作流**：Planner/Annotator/Critic 职责单一，Critic 负责防幻觉
> 3. **双重证据**：知识图谱名字重合 + 簇内表达实测检出率，两个数字都过了才放行
> 4. **审计追踪 + 响应缓存**：ProvenanceTracker 记录每步操作，缓存让大模型这一环也能逐字复现
>
> 谢谢！"
